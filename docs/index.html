Why md2office

Everything a document build needs, in one import — no scripts to copy between repos.

📄

Bring your own template

Pass a Word reference template (.docx/.dotx) via --template for a custom cover and header classification. No template? Pandoc's built-in default gives a clean standard look.

🔖

Header injection

Title and bilingual classification go into every page header and the core document metadata automatically.

📊

Table fixes

Pandoc tables are rewritten to 100% autofit width with explicit borders, so LibreOffice stops crushing them.

⌨️

Code styling

SourceCode and VerbatimChar get Consolas 9pt and light-grey shading.

🔁

DOCX → PDF

Headless LibreOffice with a fresh per-run profile, so concurrent conversions don't lock each other out.

🩺

Prerequisite doctor

md2office doctor checks pandoc, LibreOffice, python-docx, and the fonts the PDF needs.

How it works

One pipeline: pandoc builds the DOCX against your reference template, the package post-processes it, LibreOffice renders the PDF.

Quick start

Install, run doctor, convert. That's it.

terminal
# 1. install
pip install md2office

# 2. check prerequisites
md2office doctor

# 3. convert (supply your own reference template)
md2office docx --template template.dotx report.md report.docx --classification "Protected A"
md2office pdf  --template template.dotx report.md report.pdf

No template handy? Omit --template and pandoc's built-in reference document is used instead — still clean, just without a custom cover or header classification. The title still defaults to your YAML frontmatter.

Project structure

One Markdown file becomes one document. Keep everything a document needs in a single folder, and point md2office at the master file.

project layout
docs/
  report.md        # master document
  chapter-2.md     # optional: long sections as separate files
  images/
    diagram.png
template.dotx     # your Word reference template (user-supplied)
output/            # generated files (gitignore this)
  report.docx
  report.pdf

One folder per document

Images and attachments resolve relative to the Markdown file's folder, which is automatically on pandoc's resource path. Add more with -r <dir>.

🏷️

Frontmatter drives the header

The title:, classification:, author, and version in YAML frontmatter are written into the page headers and cover metadata.

⚡

Code, styled for free

Fenced code blocks get monospace 9pt and shading automatically. Mermaid blocks (```mermaid) render when mmdc is installed.

📑

TOC & page breaks

A static table of contents is inserted at the top. Drop a \newpage, or pass --page-breaks sections to start each Heading1 on a new page.

convert
cd docs
md2office pdf --template ../template.dotx report.md ../output/report.pdf

Multi-chapter books: md2office doesn't assemble multiple files. Keep one master file per document, or combine chapters first (e.g. cat chapters/*.md > book.md) and convert once.

Options

Everything is exposed on the CLI and through ConvertOptions.

OptionDefaultMeaning

classificationUnclassified | Non classifiéSensitivity label in every page header
number_sectionsFalsePass --number-sections to pandoc
code_styleTrueConsolas 9pt + shading on code styles

font"default""arial" switches the document font
mermaid"auto"Render ``` ```mermaid``` blocks (needs mmdc)

Library

Use it directly from Python — no shell needed.

python
import md2office

md2office.to_docx("report.md", "report.docx",
                  template="template.dotx",
                  title="My Report", classification="Protected A")
md2office.to_pdf("report.md", "report.pdf", template="template.dotx")

# fine-grained control
from md2office import ConvertOptions, to_pdf

opts = ConvertOptions(template="template.dotx",
                           number_sections=True, font="arial",
                           page_breaks="sections")
to_pdf("report.md", "report.pdf", options=opts)
